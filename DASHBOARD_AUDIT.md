## 3. Widget Inventory

### WeatherWidget
**File:** `src/components/WeatherWidget.jsx`

**Data displayed:** 7-day daily forecast — day name, weather icon (WMO code), max/min °C, precipitation sum mm. Clickable day cards expand a horizontally-scrollable hourly panel at 3-hour intervals (time, icon, temp, precipitation probability %, wind speed km/h).

**API URL (built from `LOCATION` in `src/config.js`):**
```
https://api.open-meteo.com/v1/forecast
  ?latitude=55.9533&longitude=-3.1883
  &daily=temperature_2m_max,temperature_2m_min,precipitation_sum,weathercode
  &hourly=temperature_2m,precipitation_probability,weathercode,windspeed_10m
  &timezone=Europe%2FLondon
```
No API key. Refresh: 15 minutes.

**localStorage keys:** None.

**User interactions:**
- Click any day card — toggles hourly panel (re-click collapses)
- ↻ button — manual refresh

**Known limitations:**
- Hourly panel uses `max-height` CSS transition, not an animated mount
- 7-day grid (`grid-cols-7`) can be tight (~43 px/cell) on 320 px mobile screens
- No `current_weather` block — no "right now" conditions

### SunsetWidget
**File:** `src/components/SunsetWidget.jsx`

**Data displayed:** 5-day sunset quality scores (0–100) with label (Poor → Spectacular), sunset time, animated SVG score rings. Best day badged. Clicking a day expands a detail panel: cloud layer bars (high/mid/low), humidity, visibility, rain chance.

**API URL (built from `LOCATION`):**
```
https://api.open-meteo.com/v1/forecast
  ?latitude=55.9533&longitude=-3.1883
  &daily=sunset
  &hourly=cloudcover,cloudcover_low,cloudcover_mid,cloudcover_high
         ,precipitation_probability,relative_humidity_2m,visibility,weathercode
  &timezone=Europe%2FLondon
  &forecast_days=5
```
No API key. Refresh: 30 minutes.

**Scoring algorithm** (ported from `sunset_notifier.py`):
- +35 pts: mid-level cloud — Gaussian peaked at 40%, σ=20%
- +20 pts: high cloud — linear
- −20 pts: low cloud — linear
- −10 pts: humidity above 70% — linear, full at 100%
- −10 pts: precipitation probability above 30% — hard cut
- −5 pts: visibility below 10 km — linear
- Raw range [−45, +55] shifted by +45 → clamped [0, 100]

**localStorage keys:** None.

**Known limitations:**
- If `findHourlyIndex` returns -1 (no hourly data at the exact sunset hour), scoring uses hardcoded fallbacks: cloudcover 50, cloudLow 30, cloudMid 20, cloudHigh 10, precipProb 0, humidity 70, visibility 10000
- WMO fallback lookup uses nearest lower code — can mismatch for unusual codes

### StockWidget
**File:** `src/components/StockWidget.jsx`

**Data displayed:** Compact list: ticker, current price (USD), 24h change (+/−$ and %), sparkline (last 8 hourly closes). Expandable detail: SVG line chart with area fill, crosshair tooltip, range selector (1D/3D/1W/1M), OHLC + volume stats.

**API URLs:**
```
Yahoo Finance v8 chart (via CORS proxies):
  https://query2.finance.yahoo.com/v8/finance/chart/{TICKER}?range={range}&interval={interval}

Proxy 1 (primary):   https://corsproxy.io/?<encoded>
Proxy 2 (fallback):  https://api.allorigins.win/raw?url=<encoded>
```

| Range | `range` | `interval` | Notes |
|---|---|---|---|
| Summary/sparkline | `5d` | `1h` | Always fetched; last 8 pts = sparkline |
| 1D | `1d` | `5m` | Empty outside market hours |
| 3D | `5d` | `1h` | Client-side filtered to last 3 days |
| 1W | `5d` | `1h` | Full 5-day fetch |
| 1M | `1mo` | `1d` | Daily bars |

Fetch strategy: sequential with 400ms stagger. One auto-retry after 1.5s. Per-request timeout: 10s. Refresh: 5 minutes.
Price change: `(regularMarketPrice - chartPreviousClose) / chartPreviousClose`.

**localStorage keys:**
- `dashboard_stockTickers` — string array. Default: `["NVDA","GOOGL","AMZN","AVGO","AMD","SOFI","PLTR","NVO"]`.

**Known limitations:**
- Yahoo Finance is unofficial — no SLA, may break without notice
- CORS proxies are free public services with no SLA
- 8 tickers × 400ms stagger = ~3.6s minimum initial load
- Chart cache lives in component state — lost on re-render/reload
- 1D chart shows "No intraday data — market may be closed" outside US hours

### CIMAWidget
**File:** `src/components/CIMAWidget.jsx`

**Data displayed:** MCQ practice for CIMA BA1–BA4 modules. Module tabs with per-module colour theming. Per-module progress bar and accuracy. Overall mini progress bars for all 4 modules. Question card with A/B/C/D options, explanation on answer, difficulty indicator. Streak badge (with 🔥 at ≥7 days). Collapsible study history (last 10 of 50 stored). Reset-module control.

**API:** None — local `src/data/cima-questions.json`.

**Data file status:** File exists but all four module arrays are currently empty — `{"BA1":[],"BA2":[],"BA3":[],"BA4":[]}` (47 bytes). The widget renders a "No questions available" fallback until the file is populated.

**Question modes:**
- **Random** — picks from unattempted questions first, then repeats pool
- **Review** — picks from spaced-repetition review queue (questions due by today's date)
- **Weakest** — picks from the topic with lowest accuracy in the active module
- **Daily** — deterministic by day-of-year: `questions[module][dayOfYear % module.length]`

**Spaced repetition:** Incorrect answers add to review queue at interval=1 day. Correct review answers double the interval (max 30 days). Wrong-again resets to 1 day.

**localStorage keys:**
- `dashboard_cima_activeModule` — string. `'BA1'` | `'BA2'` | `'BA3'` | `'BA4'`. Default: `'BA1'`.
- `dashboard_cima_attempts` — object keyed by question ID: `{ attempts, correct, bookmarked, lastAttempted }`.
- `dashboard_cima_reviewQueue` — array: `[{ questionId, lastAttempted, interval, timesWrong }]`.
- `dashboard_cima_streak` — `{ current: number, best: number, lastStudyDate: string }`. `lastStudyDate` is ISO `YYYY-MM-DD`.
- `dashboard_cima_history` — last 50 attempt records: `[{ questionId, module, topic, correct, date }]`.
- `dashboard_cima_dailyCompleted` — `{ [isoDate]: { [module]: true } }`. Tracks which modules' daily Q was done each day.

**Grid:** `lg:col-span-2` — spans 2 columns on desktop. Defined in `App.jsx` `WIDGET_SPAN` map.

**Known limitations:**
- `cima-questions.json` is currently empty — widget is non-functional until populated
- Question schema expected: `{ id, module, topic, question, options: {A,B,C,D}, correct, difficulty, explanation }`

### `src/hooks/useFetchData.js`
Shared fetch hook used by `WeatherWidget`, `PollenWidget`, `SunsetWidget`:
```js
export function useFetchData(url, refreshInterval)
// Returns: { data, loading, error, lastUpdated, refresh }
```
On mount: fetches immediately, then sets interval if `refreshInterval` is truthy. Handles loading/error/lastUpdated state. Logs errors to console.

Note: `NewsWidget` and `StockWidget` do not use this hook — they have bespoke fetch logic (multi-feed fallback and sequential-with-stagger respectively).

---

### `src/utils/migrateStorage.js`
One-time migration from legacy localStorage key names to `dashboard_` prefix. Called at module load in `App.jsx` before any `useState` initialiser:
```js
migrateStorage()  // App.jsx line 14
```
Migrated keys:
- `wordStats` → `dashboard_wordStats`
- `wordVoteDate` → `dashboard_wordVoteDate`
- `stockTickers` → `dashboard_stockTickers`
- `germanStats` → `dashboard_germanStats`
- `germanStreak` → `dashboard_germanStreak`
- `darkMode` → `dashboard_darkMode`

Each migration copies the value to the new key (if not already set) then deletes the old key. A no-op on subsequent loads once migration is complete.

---

### `src/components/ErrorBoundary.jsx`
Class-based per-widget error boundary. Renders a fallback card (⚠️ + "Reload Widget" button) on runtime crash. Resets via `this.setState({ hasError: false })` — does not re-fetch data. One `ErrorBoundary` wraps each widget in `App.jsx`'s grid — a crash in one widget does not affect others.
